** Scope Note

The three parallel metadata layers in Hoard, each
operating at a different pace: Strata (identity and
meaning — slow), Structural (organization and
navigation — medium), and Flow (dynamics and feedback
— fast, deferred).  Overlays are not containers but
lenses: the same card appears in all three, described
differently by each.

** Notes

Overlays map directly to Brand's pace layers.

*Strata* is the slowest layer.  It captures what
things are: preferred terms, scope notes, broader/
narrower/related terms, provenance.  Strata predicates
answer the question "what is this entity and how does
it relate to other entities?"  Identity changes rarely
and deliberately.

*Structural* is the middle layer.  It captures how
things are organized: holon membership, ordering,
expression preferences, navigation.  Structural
predicates answer the question "where does this entity
appear and how is it presented?"  Organization changes
more frequently than identity — a card can be added
to new holons, reordered, given new expressions.

*Flow* is the fastest layer.  It captures dynamics:
feedback, state changes, processes, living
relationships.  Flow is deferred in the current
implementation but its design space is reserved.
Flow predicates will answer the question "what is
happening to this entity right now?"

The key principle: overlays are implicit in predicates.
A quad's predicate determines which overlay it belongs
to.  v:pt (preferred term) is Strata.  v:h-member
(holon membership) is Structural.  There is no
separate "overlay" field — the vocabulary encodes the
layer.

This design means overlays can be implemented on git
branches: the Strata branch changes rarely (identity
is slow), the Structural branch changes with each new
holon or reorganization, and Flow (when implemented)
would change continuously.  Each branch moves at its
own pace, and merges propagate changes between layers.
