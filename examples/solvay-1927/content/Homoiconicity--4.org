** Scope Note

The property of a system whose data structures and its
code share the same representation — "the program is
the data is the program."  Originating in Lisp, where
programs are lists that can manipulate themselves, the
principle extends to any system where the structures
that describe the world and the structures that operate
on it are the same thing.

** Notes

In Lisp, code and data are both S-expressions — lists
of atoms.  A program can inspect, modify, and generate
other programs because there is no representational
boundary between what the machine executes and what it
reasons about.  Macros exploit this: they are programs
that write programs, transforming code before it runs.

Hoard extends this principle beyond programming.  The
data structures in a hord — cards, quads, vocabulary
terms, holons — are simultaneously the content being
managed and the instructions for how to manage it.
When an AI processes a hord, the structure of the data
generates the harness: the context, constraints, and
relationships that shape how the model works with the
material.  There is no separate "rules" layer that must
be maintained independently of the data.  Maintaining
the hord maintains the harness.

This is why rules-based harnesses become brittle as
models improve.  A harness built as a separate layer of
instructions is frozen at the moment it was written —
tuned to the weaknesses of the model it was designed
for.  When the model changes, the harness must be
manually updated.  A homoiconic system has no such gap:
the harness is regenerated each time the data is
processed, shaped by whatever the model is now capable
of understanding.

The principle connects to legal code, natural language,
and programming as a continuum.  If all three are
"code" — formal structures that constrain and enable
action — then homoiconicity means the evidence is the
design.  The thing and its description are the same
artifact.
